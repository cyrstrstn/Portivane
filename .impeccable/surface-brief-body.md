# Tunnel dashboard

Mode: operate

Audience: self-hosting hobbyists publishing a local service through Cloudflare Tunnel.
Job: find a likely web server, connect an account, choose an available subdomain under the authorized domain, and control the tunnel.
Primary task: search or select a local web service and publish it securely.
Content: real discovered-port data and persisted tunnel definitions; sample states in development are labeled as examples.
Constraints: local-only management UI, keyboard access, responsive operation, no exposed Cloudflare secrets, existing DNS records remain untouched, and clear error/log states.

## Direction contract

THESIS: Public reachability appears as a narrow diffracted edge around an otherwise quiet local workspace; it refuses the generic sidebar plus summary-card dashboard.

OWN-WORLD: Cloud-white fields, slate ink, mist rules, and mint-to-violet spectral edges used only for focus and live routes; thin humanist type and precise outlined controls.

STORY: Search likely web services, understand the selected localhost-to-hostname route, see the domain authorized during Cloudflare login, choose an available subdomain, then publish and verify it.

FIRST VIEWPORT: A narrow identity/status header sits above a two-column field: the service index occupies one third and the selected route occupies two thirds, with the single Publish action at the route's far edge. A live tunnel gains a spectral perimeter and animated route trace.

FORM: Diffracted Cloud Edge, seventh in the grounded list, adopted from the challenger hand; seed 3b49cfc9.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

Memorable moment: starting a tunnel sends one restrained spectral trace from the local port through Cloudflare to the public hostname, then settles into a static live edge.

Unresolved: final public product name and code-signing identities for packaged releases.
